# AdminZero — Principal Architect & UI/UX Spec

Product name: **AdminZero** (the original spec called it NexusITSM). A modular, human-centric ITSM,
Torii-style SaaS Governance, Hardware/Software ITAM (CMDB), and Enterprise JIT Password Vault platform.

Stack: Next.js (App Router, static export for GitHub Pages) + TypeScript + Tailwind CSS v4 + Zustand + lucide-react.
Backend (Phase 5): FastAPI in `backend/`, Google Cloud Secret Manager, Anthropic SDK, Cloud Run.
All work happens on the `develop` branch. Pages deploys from `develop`.

## 1. Zero-placeholder engineering law
- **No lazy code or dead buttons.** Never write `// TODO`, `// implement later`, or static unclickable mockups. Every
  button, modal, slide-over drawer, filter, toggle and form is wired to the reactive Zustand store
  (`src/store/usePlatformStore.ts`), and from Phase 5 to the FastAPI backend, with optimistic updates and toast feedback.
- **Human-centric AI.** AI automates trivial triage, multilingual translation, template mapping and log correlation so
  human agents can focus on empathetic, high-touch problem-solving.
- **Modular feature flags.** All 5 modules (`itsm_core`, `ai_agents`, `torii_saas`, `itam_cmdb`, `password_vault`) toggle
  ON/OFF at runtime, immediately updating navigation and dashboard widgets without breaking layout. `itsm_core` is the
  platform foundation and is locked ON.

## 2. Design system (research-driven: what IT techs & admins say they want)
Revised after reviewing what daily users praise and complain about in ServiceNow, Freshservice, Zendesk,
Jira Service Management and Torii (G2, Capterra, vendor communities) plus accessibility guidance for ops dashboards.
- **Dark mode is optional: Automatic (default, follows the OS), Light or Dark, applied everywhere.** High contrast is a
  separate on/off switch next to it (AAA). ServiceNow admins complain dark mode only covers part of the
  product; light text on dark causes halation in bright offices. Users pick per account (top bar).
- **Calm, neutral palette.** Neutral grey surfaces (Tailwind gray), never pure black backgrounds or pure white text.
  One enterprise-blue brand accent (the `indigo-*` classes are remapped to blue in `src/app/theme.css`). No neon glows,
  no decorative blur blobs, no glassmorphism on cards (it also broke fixed positioning).
- **Semantic surface tokens** — use these instead of hex values: `bg-canvas`, `bg-sidebar`, `bg-surface` (cards),
  `bg-raised` (popovers/menus), `bg-raised-hover`, `bg-sunken`, `bg-code`, `bg-scrim`, `text-onaccent`, `shadow-card`.
  Theme values are generated by `python3 scripts/gen_theme.py src/app/theme.css` — never hand-edit theme.css.
- **Light theme mirrors scales** so existing `text-slate-*` / accent text shades stay readable; solid fills (500+) keep
  their colour. Use `text-onaccent` (not `text-white`) on coloured buttons.
- **Colour-blind safe status:** meaning never relies on colour alone. Every status/priority/tool state has an icon shape
  and a text label (check = fine, triangle = degraded/P2, octagon = outage/P1, pause = waiting, wrench = maintenance).
- **Calm motion:** only the P1 icon pulses (not whole badges); `prefers-reduced-motion` disables animation.
- Fonts: Inter (UI), JetBrains Mono (IDs, timers, KB IDs, JSON). Keyboard shortcuts shown with `<Kbd>`.
- Global Cmd+K palette; right-side drawers for tickets/assets/SaaS; all modals portal to `<body>`.

### Features people love (keep them)
- ServiceNow: multiple records open as tabs in one workspace; agent-assist from similar incidents; review AI activity.
- Zendesk: one unified conversation per ticket; macros/saved replies from a `/` shortcut in the composer.
- Jira Service Management: queues with live counts and quick switching; team-wide swarming; Jira links.
- Freshservice: intuitive UI, service catalog tiles, out-of-the-box automation, gamification (Arcade). Its weak spot is
  reporting — keep Reports strong.
- Torii: shadow-IT discovery, idle-seat reclaim, automation. Fixify: tier-1 self-service (password/MFA, installs).

## 3. Domain anti-patterns enforced in code (`src/lib/rules.ts`)
1. **No Jira status zoo.** Exactly 5 statuses: `AI_TRIAGED`, `ACTIVE_SWARM`, `WAITING_ON_CUSTOMER`, `WAITING_ON_VENDOR`,
   `RESOLVED_KB_LINKED`. Moving to `WAITING_*` sets `slaPaused = true` and freezes the SLA countdown. Moving to
   `RESOLVED_KB_LINKED` requires linking or creating a Knowledge Base article.
2. **No silent handoffs.** Reassigning or transferring to another swarm squad opens the mandatory `HandoffContextModal`
   (`handoffReason`, `diagnosticsAttempted`, `recommendedNextStep`) and appends a permanent Handoff Audit Card to the timeline.
3. **No assignee silos.** Kanban boards are grouped by collaborative swarm squads (configurable in Admin → Organization;
   defaults `Network & Identity`, `Endpoint & Mac`, `SaaS & Cloud Ops`, `Security & SIEM`) with overlapping agent avatars —
   never by individual assignee. Read squads from the store (`s.squads`), never from `SWARM_SQUADS` in components.
4. **Zero hardcoded secrets.** Backend loads `ANTHROPIC_API_KEY`, `DATABASE_URL`, `SIEM_WEBHOOK_SECRET`, `VAULT_KMS_KEY`
   from Google Cloud Secret Manager, with `.env.local` fallback only for offline dev.

## 4. Core schemas
`src/types/platform.ts` implements the spec's `TicketStatus`, `TicketPriority`, `SwarmSquad`, `TicketMessage` and
`Ticket` interfaces exactly; supporting entities (assets, SaaS apps, vault items, flags, telemetry) extend around them.

## Information architecture (platform restructure)
- Every page belongs to a module (`VIEW_MODULE` in `AppShell.tsx`); when a module is off, its nav section, Home widgets
  and side panels disappear and its pages fall back to Home.
- Home · ITSM (Tickets, Problems, Changes, Knowledge) · AI agents (Employee portal) · SaaS · Assets · Security (Vault) · Admin.
- The AI copilot (`CopilotPanel`, `src/lib/copilot.ts`) lives inside Tickets, Problems and Changes: similar closed tickets,
  KB matches with confidence + reasons, next best action, bilingual drafts. It suggests; humans approve.
- Knowledge pattern detection (`src/lib/patterns.ts`) clusters recurring tickets, drafts articles from real resolutions,
  and published self-service articles deflect employees in the portal before a ticket exists.
- Admin: modules, people & squads, SLA policies, no-code automations, fields & statuses (capped), AI & grounding,
  integrations, immutable audit log (every store mutation writes one).

## Accessibility (non-negotiable — a selling point)
- Standard: **WCAG 2.2 AA** in Light and Dark; **AAA contrast (7:1)** in the High contrast theme (`data-theme="contrast"`,
  also picked automatically by System when the OS asks for more contrast).
- Gates: `src/components/views/A11y.test.tsx` (axe structural rules on every page) and `npm run a11y`
  (`scripts/a11y-audit.mjs`, axe in real Chrome on 11 pages × 3 themes; runs in CI and fails the build on any violation).
- Rules: never `outline-none`; never convey state by colour alone; text-bearing fills use 600+/700 shades with
  `text-onaccent`; no translucent text (`text-x/60`) or `opacity-*` on text; every modal/drawer uses `Modal`/`Drawer`
  (focus trap + focus return); drag-and-drop always has a click/keyboard alternative; targets ≥ 24px; mark foreign-language
  text with `lang`. Public statement: Admin → Accessibility (keep it honest — list what is not done yet).

## Built by IT, for IT — and for any team size
- Keyboard-first: `?` cheat sheet, `g`+letter navigation, `j`/`k` queue, `r` reply, `/` saved replies, ⌘K palette,
  copy-ID buttons. Density: comfortable / compact (rem-scaled, honours zoom).
- Org profiles (Admin → Organization): **Solo** (one "IT" squad, no handoffs, self-approve changes with an audited reason,
  AI auto-resolves low risk, compact), **Team**, **Enterprise** (strict separation of duties, unlimited squads).
  Squads can be added, renamed and removed; work moves with them and nothing is orphaned.
